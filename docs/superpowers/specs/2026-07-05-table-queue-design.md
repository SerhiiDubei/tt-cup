# «Стіл» — електронна черга на стіл · Design Spec

**Date:** 2026-07-05
**Status:** Approved for planning
**Author:** brainstorm session (Serhii + Claude)
**Контекст:** продовження tt-cup (той самий репозиторій, база Supabase, пул гравців
`tt_players`, дизайн-мова Memphis). Живе поруч із турніром, не чіпає його механіки.

---

## 1. Goal

Вебап-кіоск для планшета, що постійно стоїть біля стола: **електронна черга** на
казуальні ігри 1v1. Принцип: якщо ніхто не грає — черга не потрібна, просто стаєш до
столу; якщо стіл зайнятий — тицяєш «Записатись у чергу» і бачиш свою позицію. Після
гри вводиться повний рахунок очок по сетах → історія + лідерборд.

Весь функціонал заточений під планшет: тільки пальці, великі кнопки (тап-таргети
≥ 64px), без hover-станів, мінімум текстового вводу.

## 2. Не-цілі (YAGNI)

- Ніяких таймерів неявки, авто-пропусків, пріоритетів — жива черга сама розбирається.
- Ніякого захисту/PIN — все відкрито на довірі; небезпечні дії лише з підтвердженням.
- Ніякої інтеграції з турнірними таблицями/рейтингом турніру — казуальні ігри живуть
  окремо від `tt_matches`.
- Один стіл. Мультистіл не проєктуємо.
- Live-табло під час гри не робимо — рахунок вводиться після гри.

## 3. Механіки (затверджені)

| Питання | Рішення |
|---|---|
| Формат | тільки 1v1 |
| Старт гри | двоє відмічаються «Ми граємо» на планшеті |
| Хто може стати до столу | якщо черга непорожня — **тільки люди з черги**; виняток: переможець попередньої гри може лишитись |
| Ротація після гри | вирішують на місці: екран «Хто далі?» пропонує «Переможець лишається» або «Обидва йдуть» |
| Рахунок | повні очки по сетах (11:9, 11:7…), кількість сетів вільна (мін. 1), «Завершити» вручну, переможець рахується автоматично |
| Неявка | без механіки — просто обирають іншого з черги |
| Вихід з черги | вільно, ✕ біля себе, з підтвердженням |
| Скасування гри | кнопка «Скасувати гру» з підтвердженням; гра не пишеться в історію |
| Новий гравець | прямо на планшеті: ім'я + селфі фронталкою → герой-аватар через існуючий пайплайн (`stylizeSelfie`), або «без селфі» з заглушкою |
| Статистика | лідерборд (W-L, поточний вінстрік) + стрічка історії ігор |
| Синхронізація | полінг ~3 сек, як у решті tt-cup |
| Захист | нема; підтвердження на: вихід з черги, скасування гри |

## 4. Архітектура

### Сторінки
- **`/table`** — кіоск. Без сайтових Nav/Footer. Адаптивна: на планшеті — кіоск,
  з телефона — ті самі дані (подивитись чергу/лідерборд). Дві внутрішні вкладки:
  «Стіл» (основна) і «Лідерборд».
- Nav сайту отримує пункт «Стіл» → `/table`.
- Nav/Footer переїжджають з кореневого `layout.tsx` у route group `(site)/layout.tsx`;
  всі існуючі сторінки переїжджають у `(site)/` (URL не змінюються). `/table` лишається
  поза групою — чистий екран. `globals.css` і шрифти лишаються в кореневому layout.

### Кіоск-специфіка
- Wake Lock API (`navigator.wakeLock.request('screen')`) з re-acquire на
  `visibilitychange` — екран планшета не засинає.
- Полінг `GET /api/table/state` кожні ~3 сек (`cache: no-store`), пауза коли вкладка
  прихована.
- Всі кнопки дій блокуються на час запиту (захист від подвійного тапу).
- Конфлікт (стан змінили з іншого пристрою): сервер повертає 409 з поясненням,
  клієнт показує коротке повідомлення і пересинхронізовується.

## 5. Дані (нова міграція)

```sql
create table public.tt_casual_games (
  id uuid primary key default gen_random_uuid(),
  a uuid not null references public.tt_players(id) on delete cascade,
  b uuid not null references public.tt_players(id) on delete cascade,
  sets jsonb not null default '[]'::jsonb,   -- [[11,9],[7,11],...] очки a:b
  winner uuid references public.tt_players(id),
  status text not null default 'active' check (status in ('active','done','cancelled')),
  started_at timestamptz not null default now(),
  ended_at timestamptz
);
-- тільки одна активна гра (один стіл)
create unique index tt_casual_one_active on public.tt_casual_games ((true)) where status = 'active';

create table public.tt_table_queue (
  id uuid primary key default gen_random_uuid(),
  player_id uuid not null unique references public.tt_players(id) on delete cascade,
  joined_at timestamptz not null default now()
);
```

- Порядок черги = `joined_at asc`.
- RLS увімкнено без політик (як у решті таблиць) — доступ тільки через server routes
  із секретним ключем.
- Лідерборд не зберігається — агрегується з `tt_casual_games (status='done')` на
  сервері при читанні стану: wins, losses, поточний streak (по `ended_at desc`).
  На клубних масштабах (сотні ігор) це дешево.

## 6. API (`/api/table/*`, всі server-side через `supaServer`)

| Route | Дія | Валідація на сервері |
|---|---|---|
| `GET /state` | `{ game, queue, players, leaderboard, recent }` — один полінг-ендпоінт | — |
| `POST /start` `{a, b}` | створити активну гру; видалити a/b з черги | нема іншої активної гри; `a ≠ b`; якщо черга непорожня — кожен з (a, b) або в черзі, або є переможцем останньої `done`-гри |
| `POST /queue/join` `{playerId}` | стати в чергу | не грає зараз; ще не в черзі |
| `POST /queue/leave` `{playerId}` | вийти з черги | запис існує |
| `POST /finish` `{gameId, sets}` | зберегти рахунок, `status='done'`, порахувати winner | гра активна; ≥1 сет; в кожному сеті числа 0–99 і не рівні; переможець матчу = більше виграних сетів; при рівності виграних сетів — 409 (догравайте вирішальний) |
| `POST /cancel` `{gameId}` | `status='cancelled'` | гра активна |

- Швидке додавання гравця — **існуючий** `POST /api/register` (ім'я → `name` і
  `nickname`; при зайнятому nickname — 409, клієнт просить інше ім'я) + існуючий
  `POST /api/avatar` (`stylizeSelfie(selfie, style)`), стилі — існуючі `STYLES`
  (`attacker | defender | allrounder | spinner`). «Без селфі» → hero з дефолтним
  `art` (заглушка), селфі можна доробити пізніше через звичайну реєстрацію.
- Race conditions: `start` — захищений унікальним індексом `tt_casual_one_active`
  (паралельний друга вставка впаде → 409); `finish`/`cancel` — update з умовою
  `status='active'` (0 rows → 409).

## 7. Екрани кіоска (`/table`, вкладка «Стіл»)

Стан-машина клієнта виводиться з `state.game`:

1. **Стіл вільний** (`game == null`)
   Великий заголовок «СТІЛ ВІЛЬНИЙ» + гігантська кнопка **«СТАТИ ДО СТОЛУ»**.
   Якщо черга непорожня — список черги тут же, і picker обмежений чергою
   (перші двоє передвибрані). Кнопка «Записатись у чергу» доступна і тут
   (люди можуть чекати, поки стіл протирають).

2. **Гра йде** (`game.status == 'active'`)
   Дві герой-картки (аватар, нік) через «VS», таймер тривалості від `started_at`.
   Черга з позиціями (1, 2, 3…) і ✕ біля кожного (confirm-діалог «Точно вийти?»).
   Кнопки: **«ГРА ЗАКІНЧИЛАСЬ»** (primary), **«ЗАПИСАТИСЬ У ЧЕРГУ»**,
   маленька «Скасувати гру» (confirm).

3. **Ввід рахунку** (локальний крок після «ГРА ЗАКІНЧИЛАСЬ»)
   Сети списком: два великих числа зі степперами «+ / −» (крок 1, довгий тап —
   швидко), кнопка «+ сет», «Завершити». Дефолт нового сета 11:9 → правиться
   степперами. «Завершити» активна тільки коли рахунок валідний. Після збереження →
   екран «Хто далі?».

4. **Хто далі?** (після `finish`, якщо черга непорожня; інакше → стан 1)
   Результат гри великим текстом + два великих варіанти:
   - **«Переможець лишається»** → picker суперника **з черги** (перший передвибраний);
   - **«Обидва йдуть»** → picker двох **з черги** (перші двоє передвибрані).
   «Почати гру» → `POST /start` → стан 2. Кнопка «Пізніше» → стан 1 (стіл вільний,
   черга стоїть).

**Вибір гравця (спільний компонент picker):** повноекранна сітка великих карток
(аватар + нік), скрол пальцем; остання картка — **«Я тут вперше +»**:
ім'я (текстове поле + клавіатура планшета) → селфі (реюз `SelfieCapture`) →
вибір стилю (4 великі кнопки з існуючими лейблами) → генерація ~10 сек
(анімація очікування в стилі Memphis) → гравець у пулі і одразу вибраний.
Фолбек «Пропустити селфі».

**Вкладка «Лідерборд»:** таблиця (аватар, нік, W-L, streak) сортування за
перемогами; нижче стрічка останніх ігор (хто-кого, рахунок по сетах, коли).

## 8. Стиль

Memphis-система з `globals.css` без змін: cream/ink, акценти (pink/cyan/yellow/blue),
Unbounded для заголовків, Onest для тексту, 3px бордери, hard shadows, великі радіуси.
Кіоск — та сама мова, але масштабніша типографіка і щільність під landscape-планшет
(основна орієнтація) з підтримкою portrait.

## 9. Тести (vitest, у `src/**/*.test.ts` як у репо)

- Підрахунок переможця з `sets` (включно з нічиєю по сетах → помилка).
- Валідація `finish` (порожні сети, рівний сет, межі очок).
- Правило eligibility для `start` (черга непорожня: з черги / переможець / чужий → відмова).
- Агрегація лідерборду (W-L, streak) з фікстурного набору ігор.

## 10. Ризики

- **Генерація аватара ~10 сек** блокує кіоск для інших → picker лишається доступним
  через «Пізніше»: генерація йде у фоні, гравець одразу створюється із заглушкою,
  `art` оновлюється коли догенерується (полінг сам підтягне).
- **Планшет офлайн/wifi-глюк** → полінг просто відновиться; дії покажуть помилку
  і не задублюються (server-side валідація + унікальні індекси).
- **Nickname-колізія** при швидкому додаванні → 409 з existing register — клієнт
  пропонує змінити ім'я (додати цифру).
